Claude Code · remote sessions

Ctrl+V for images in a remote Claude Code session

Paste a screenshot straight into Claude Code running over SSH, instead of saving it, scp-ing it across, and pasting the path.

Why it doesn't work out of the box

Claude Code reads a pasted image from the clipboard of the machine it runs on. On a headless server there is no clipboard — your screenshot is sitting on your laptop, one network hop away.

But the way it reads that clipboard is easy to intercept. On Linux it shells out to exactly two commands, and checks nothing but their exit codes — no DISPLAY, no X connection:

what Claude Code runs on Linux 
xclip -selection clipboard -t TARGETS   -o | grep -E "image/(png|jpeg|jpg|gif|webp|bmp)"
xclip -selection clipboard -t image/png -o > /tmp/<tempfile>

So you don't need a real clipboard on the server. You need a program named xclip, earlier in PATH, that answers those two calls with the image from your laptop — fetched over a reverse tunnel you already have open for the SSH session.

Arrows show where the image data travels. The request goes the other way: nothing leaves your machine until you actually press Ctrl+V on the server.

What you need

Your machine
  • Python 3.7 or newer
  • macOS, Linux, or Windows
  • ssh, or Eternal Terminal (et)
The server
  • Linux, with Claude Code installed
  • curl or wget
  • Write access to a directory in PATH
  • Loopback ports 8377–8420, one per open session

Setup

1

Install the clipboard server

Your machine

Save this as ~/.local/bin/clip-image-server. It listens on loopback only and converts whatever is in your clipboard to PNG on demand.

~/.local/bin/clip-image-server 
#!/usr/bin/env python3
"""Serve the local clipboard image over loopback for a remote Claude Code session."""

import os
import shutil
import subprocess
import sys
import tempfile
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

PORT = int(os.environ.get("CLIP_IMAGE_PORT", "8377"))
TOKEN_PATH = os.path.expanduser("~/.config/clip-image-server/token")
PNG_MAGIC = b"\x89PNG"

try:
    with open(TOKEN_PATH) as fh:
        TOKEN = fh.read().strip()
except OSError:
    TOKEN = ""


def run(cmd):
    try:
        return subprocess.run(cmd, capture_output=True, timeout=30)
    except Exception:
        return None


def macos_png():
    d = tempfile.mkdtemp(prefix="clip-image-server.")
    path = os.path.join(d, "clip.png")
    try:
        r = run([
            "osascript",
            "-e", "set png_data to (the clipboard as «class PNGf»)",
            "-e", 'set fp to open for access POSIX file "%s" with write permission' % path,
            "-e", "write png_data to fp",
            "-e", "close access fp",
        ])
        if r is None or r.returncode != 0:
            return None
        with open(path, "rb") as fh:
            return fh.read() or None
    except Exception:
        return None
    finally:
        shutil.rmtree(d, ignore_errors=True)


def linux_png():
    for cmd in (["wl-paste", "--type", "image/png"],
                ["xclip", "-selection", "clipboard", "-t", "image/png", "-o"]):
        r = run(cmd)
        if r and r.returncode == 0 and r.stdout.startswith(PNG_MAGIC):
            return r.stdout
    return None


def windows_png():
    d = tempfile.mkdtemp(prefix="clip-image-server.")
    path = os.path.join(d, "clip.png")
    try:
        r = run(["powershell", "-NoProfile", "-NonInteractive", "-Sta", "-Command",
                 "Add-Type -AssemblyName System.Windows.Forms;"
                 "$img = [System.Windows.Forms.Clipboard]::GetImage();"
                 "if ($null -eq $img) { exit 1 };"
                 "$img.Save('%s', [System.Drawing.Imaging.ImageFormat]::Png)" % path])
        if r is None or r.returncode != 0:
            return None
        with open(path, "rb") as fh:
            return fh.read() or None
    except Exception:
        return None
    finally:
        shutil.rmtree(d, ignore_errors=True)


if sys.platform == "darwin":
    read_png = macos_png
elif sys.platform.startswith("win"):
    read_png = windows_png
else:
    read_png = linux_png

_cache_key = None
_cache_png = None


def clipboard_stamp():
    """Cheap change detector. macOS only; elsewhere caching is simply skipped."""
    if sys.platform != "darwin":
        return None
    r = run(["osascript", "-e", "clipboard info"])
    return r.stdout if r and r.returncode == 0 else None


def clipboard_png():
    global _cache_key, _cache_png
    key = clipboard_stamp()
    if key is not None and key == _cache_key:
        return _cache_png
    png = read_png()
    _cache_key, _cache_png = key, png
    return png


class Handler(BaseHTTPRequestHandler):
    protocol_version = "HTTP/1.1"

    def log_message(self, fmt, *a):
        pass

    def _respond(self, code, body=b"", ctype="text/plain"):
        self.send_response(code)
        self.send_header("Content-Type", ctype)
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        if body:
            self.wfile.write(body)

    def do_GET(self):
        if TOKEN and self.headers.get("X-Clip-Token", "") != TOKEN:
            return self._respond(403)
        route = self.path.split("?")[0]
        if route == "/id":
            # lets the shim recognise us while it scans ports for a live tunnel
            return self._respond(200, b"clip-image-server\n")
        if route not in ("/check", "/png"):
            return self._respond(404)
        png = clipboard_png()
        if not png:
            return self._respond(404, b"no image on clipboard\n")
        if route == "/check":
            return self._respond(200, b"image/png\n")
        return self._respond(200, png, "image/png")


def main():
    if not TOKEN:
        print("warning: no token at %s, serving unauthenticated" % TOKEN_PATH, file=sys.stderr)
    print("clip-image-server listening on 127.0.0.1:%d" % PORT, file=sys.stderr)
    ThreadingHTTPServer(("127.0.0.1", PORT), Handler).serve_forever()


if __name__ == "__main__":
    main()
Verified where

The macOS branch is tested end to end. The Linux and Windows clipboard branches follow the same pattern but have not been run — check them before relying on them.

3

Install the xclip shim

The server

Save this as /usr/local/bin/xclip — or anywhere in PATH that comes before a real xclip. Paste your token into the TOKEN line.

With several machines tunnelled to one server, it sends each session to its own machine's tunnel, found from the kernel rather than the environment. When it cannot tell which tunnel is yours, it refuses to paste rather than guess.

/usr/local/bin/xclip 
#!/bin/sh
# xclip shim -- serves the client machine's clipboard to a remote Claude Code session.
#
# Claude Code fetches a pasted image with exactly two calls:
#   xclip -selection clipboard -t TARGETS   -o
#   xclip -selection clipboard -t image/png -o
# Both are answered over a reverse tunnel back to the client.
#
# Each client machine tunnels on its own port, claimed by binding it (see
# clip_et on the client side). Several machines can therefore be tunnelled here
# at once, and "the first port that answers" is the WRONG one for all but one of
# them -- it would hand this session another machine's clipboard, leaking
# whatever that machine last copied. So the port is resolved by ownership:
#
#   1. $CLIP_IMAGE_PORT            explicit override, always wins
#   2. the tunnel whose owning sshd is connected to THIS session's client
#   3. the only clipboard on the range, if there is exactly one
#   4. otherwise refuse -- never serve a clipboard we cannot attribute
#
# Step 2 reads the peer address of the sshd holding each listener. That comes
# from the kernel, not from anything a session can set, so a session cannot
# claim another machine's tunnel by editing its own environment.
#
# Anything that is not one of those two calls goes to the real xclip, if present.

TOKEN='PASTE_YOUR_TOKEN_HERE'
PORT_MIN=8377
PORT_MAX=8420
MAGIC='clip-image-server'

if command -v curl >/dev/null 2>&1; then
	HTTP=curl
elif command -v wget >/dev/null 2>&1; then
	HTTP=wget
else
	HTTP=''
fi

# get <port> <path> <timeout> -- body on stdout, non-zero unless the request succeeds
get() {
	case "$HTTP" in
		curl) curl -fs --connect-timeout 1 --max-time "$3" \
		           -H "X-Clip-Token: $TOKEN" "http://127.0.0.1:$1$2" ;;
		wget) wget -q -O - --connect-timeout=1 --timeout="$3" \
		           --header="X-Clip-Token: $TOKEN" "http://127.0.0.1:$1$2" ;;
		*)    return 1 ;;
	esac
}

# client_ip -- the machine the human running this session is actually sitting at.
client_ip() {
	conn=$SSH_CONNECTION

	# Inside tmux a pane keeps the environment of whichever client created the
	# session. Re-attach from a second machine and that pane still advertises
	# the first machine's IP, which would resolve to the first machine's
	# clipboard. Ask tmux which client is attached NOW instead of trusting the
	# environment we inherited.
	if [ -n "$TMUX" ] && command -v tmux >/dev/null 2>&1; then
		cpid=$(tmux display-message -p '#{client_pid}' 2>/dev/null)
		if [ -n "$cpid" ] && [ -r "/proc/$cpid/environ" ]; then
			fresh=$(tr '\0' '\n' <"/proc/$cpid/environ" 2>/dev/null |
			        sed -n 's/^SSH_CONNECTION=//p' | head -1)
			[ -n "$fresh" ] && conn=$fresh
		fi
	fi

	printf '%s\n' "$conn" | awk '{print $1}'
}

# ports_owned_by <ip> -- ports in range whose reverse tunnel belongs to <ip>.
ports_owned_by() {
	_ip=$1
	[ -n "$_ip" ] || return 0
	command -v ss >/dev/null 2>&1 || return 0

	# Every listener in range, with the pid holding it.
	ss -ltnpH 2>/dev/null | awk -v min="$PORT_MIN" -v max="$PORT_MAX" '
		{
			addr = $4
			sub(/.*:/, "", addr)
			if (addr+0 < min || addr+0 > max) next
			if (match($0, /pid=[0-9]+/))
				print addr, substr($0, RSTART+4, RLENGTH-4)
		}' | sort -u | while read -r _port _pid; do
		# The sshd holding a -R listener also holds that client's connection,
		# so its peer address identifies the machine the tunnel belongs to.
		_peers=$(ss -tnpH 2>/dev/null | awk -v pid="$_pid" '
			index($0, "pid=" pid ",") || index($0, "pid=" pid ")") {
				peer = $5
				sub(/:[0-9]+$/, "", peer)
				gsub(/[][]/, "", peer)
				print peer
			}' | sort -u)

		# Exactly one peer means the holder serves exactly one client, so the
		# attribution is certain. A legacy `et -r` tunnel is held by etserver,
		# which holds EVERY ET session at once -- picking one of its peers
		# would be a guess, and guessing whose clipboard this is is precisely
		# the leak being prevented. Leave it unattributed instead.
		[ "$(printf '%s\n' "$_peers" | grep -c .)" -eq 1 ] || continue
		[ "$_peers" = "$_ip" ] && printf '%s\n' "$_port"
	done
}

discover() {
	# 1. Explicit override always wins.
	if [ -n "$CLIP_IMAGE_PORT" ]; then
		printf '%s\n' "$CLIP_IMAGE_PORT"
		return 0
	fi

	myip=$(client_ip)

	# 2. The tunnel this client machine owns.
	for p in $(ports_owned_by "$myip"); do
		if [ "$(get "$p" /id 3 2>/dev/null)" = "$MAGIC" ]; then
			printf '%s\n' "$p"
			return 0
		fi
	done

	# 3./4. Nothing attributable. Count what is actually out there: with a
	# single clipboard tunnelled here there is nothing to confuse it with, so
	# use it. With two or more we cannot tell which is ours, and guessing means
	# handing this session someone else's clipboard -- refuse instead.
	found=''
	n=0
	p=$PORT_MIN
	while [ "$p" -le "$PORT_MAX" ]; do
		if [ "$(get "$p" /id 3 2>/dev/null)" = "$MAGIC" ]; then
			n=$((n + 1))
			[ -z "$found" ] && found=$p
		fi
		p=$((p + 1))
	done

	if [ "$n" -eq 1 ]; then
		printf '%s\n' "$found"
		return 0
	fi
	if [ "$n" -gt 1 ]; then
		printf '%s\n' "xclip: $n clipboards are tunnelled to this host and none belongs to this session (client ${myip:-unknown}); refusing to paste rather than risk another machine's clipboard. Set CLIP_IMAGE_PORT to choose one deliberately." >&2
	fi
	return 1
}

self=$(cd "$(dirname "$0")" 2>/dev/null && pwd)/$(basename "$0")
real=''
oldifs=$IFS
IFS=:
for dir in $PATH; do
	cand="$dir/xclip"
	[ -x "$cand" ] || continue
	[ "$cand" = "$self" ] && continue
	real="$cand"
	break
done
IFS=$oldifs

passthrough() {
	[ -n "$real" ] && exec "$real" "$@"
	exit 1
}

case " $* " in
	*" -t TARGETS "*)
		port=$(discover) && get "$port" /check 5 && exit 0
		passthrough "$@"
		;;
	*" -t image/png "*)
		port=$(discover) && get "$port" /png 30 && exit 0
		passthrough "$@"
		;;
esac

passthrough "$@"

Then lock it down — the token lives inside the file, so only the user running Claude Code should be able to read it:

chmod 700 /usr/local/bin/xclip
command -v xclip          # must print your shim's path
4

Connect with a reverse tunnel

Your machine

Start the clipboard server, then carry it over an ssh -R tunnel and attach with et separately. Tunnelling with et -r instead is what makes concurrent sessions collide — see the warning below. These are the manual steps; clip_et does all of it in one command.

python3 ~/.local/bin/clip-image-server &

# Claim the server-side port by BINDING it, never by checking first.
# ExitOnForwardFailure turns a collision into a harmless non-zero exit,
# so you can just try the next port.
ssh -o ExitOnForwardFailure=yes -fN -R 8377:127.0.0.1:8377 user@host

# then attach -- deliberately with NO -r, so etserver never binds for you
et user@host
Never tunnel with et -r

A reverse-tunnel port is bound by the etserver daemon, not by your session. When a second client asks it to bind a port that is already held, etserver does not reject that one session — it abort()s (TcpSocketHandler.cpp:156, "Tried to listen twice on the same port"), taking down every session on the host. The daemon that is your way in is the thing that dies.

Checking first does not help: asking which port is free and using the answer a moment later is a race, and every client asking at once is told the same port is free. ssh -R has no such failure mode — a collision there is a warning, sshd stays up, and the bind attempt is the test.

Session terminated printed after logout is just a normal goodbye. The failure looks like the same words appearing instead of a prompt.

Paste

The server

Take a screenshot to the clipboard, then press Ctrl+V in Claude Code on the server. Not Cmd+V — on macOS that is the terminal's own paste, which only carries text. Ctrl+V passes through as a raw ^V, which is what Claude Code listens for.

Check that it works

Put an image on your clipboard, then run this on the server, inside the tunnelled session:

xclip -selection clipboard -t TARGETS -o

image/png means the whole chain is live. Silence means it isn't — and the shim fails in about 12 ms rather than hanging, so a dead tunnel only ever costs you a "no image found", never a frozen session.

Optional: one command instead of three

clip_et starts the bridge only when it's needed and stops it when the connection ends, unless another session is still using it. Extra arguments go straight to et. clip_reap lists tunnels left behind by sessions that never got to clean up, and closes them only when you add -f. Save the file as clip_et.zsh and add source /path/to/clip_et.zsh to ~/.zshrc.

clip_et.zsh 
# Clipboard image bridge for remote Claude Code sessions -- source from ~/.zshrc.
#
#   clip_et <host> [et args...]   connect with the clipboard tunnelled alongside
#   clip_reap [-f]                report (and with -f, close) orphaned tunnels
#
# Serves the local clipboard on 127.0.0.1:$CLIP_IMAGE_PORT and reverse-tunnels it,
# so Ctrl+V pastes screenshots on the remote. Lives only as long as the connection.

# Report tunnel masters whose session is gone -- and, only with -f, close them.
#
# `ssh -fN` detaches to init, so nothing reaps it: clip_et's own teardown runs
# only when `et` returns. Close the terminal window, quit the terminal app or
# kill the shell, and that master keeps its remote port for the life of the
# host. The range is finite, so leaks do eventually block connecting.
#
# Deliberately NOT called automatically, and it never acts without -f:
#   * an earlier auto-running version also reaped on "control socket missing",
#     which races a tunnel that simply has not finished connecting yet;
#   * closing an ssh nobody asked to close is not this function's decision.
#
# The only signal is the PID embedded in the control path
# (clip-et-<pid>-<rand>.ctl): the shell that ran clip_et. A living PID means
# leave alone, so this can only ever under-reap.
clip_reap() {
    local act=0
    [[ $1 == -f ]] && act=1
    local proc cpath base spid n=0
    for proc in ${(f)"$(pgrep -f 'ControlPath=[^ ]*clip-et-' 2>/dev/null)"}; do
        [[ -n $proc ]] || continue
        [[ $(ps -o comm= -p "$proc" 2>/dev/null) == *ssh ]] || continue
        cpath=$(ps -o command= -p "$proc" 2>/dev/null |
                sed -n 's/.*ControlPath=\([^ ]*\).*/\1/p')
        [[ -n $cpath ]] || continue
        base=${cpath:t}
        spid=${${base#clip-et-}%%-*}
        [[ $spid == <-> ]] || continue
        kill -0 "$spid" 2>/dev/null && continue
        (( n++ ))
        if (( act )); then
            print -r "clip_reap: closing ssh $proc (owner $spid gone)"
            kill "$proc" 2>/dev/null
            rm -f "$cpath"
        else
            print -r "clip_reap: orphan ssh $proc, owner $spid gone"
        fi
    done
    (( n )) || { print -r "clip_reap: no orphaned tunnels"; return 0 }
    (( act )) || print -r "clip_reap: nothing closed -- run 'clip_reap -f' to close them"
}

clip_et() {
    local host="${1:?usage: clip_et <host> [et args...]}"
    shift
    local local_port="${CLIP_IMAGE_PORT:-8377}"
    # The ceiling must match PORT_MAX in the server's xclip shim, which only
    # scans PORT_MIN..PORT_MAX: a port claimed above it is invisible to the shim
    # and paste silently stops working. If something permanently squats the
    # bottom of the range (legacy `et -r` tunnels held by etserver, say), raise
    # CLIP_PORT_MIN past it rather than paying a probe per squatter on every
    # connect.
    local port_min="${CLIP_PORT_MIN:-8377}" port_max="${CLIP_PORT_MAX:-8420}"
    local pid= remote_port= ctl=

    # CLIP_ET_DEBUG=1 clip_et host  ->  where the time actually goes. Off by default.
    zmodload zsh/datetime 2>/dev/null
    local _t0=${EPOCHREALTIME:-0}
    _clip_lap() {
        [[ -n $CLIP_ET_DEBUG ]] || return 0
        printf 'clip_et: %-22s %6.2fs\n' "$1" $(( ${EPOCHREALTIME:-0} - _t0 )) >&2
    }

    # One bridge per machine, shared by every session
    if ! nc -z 127.0.0.1 "$local_port" 2>/dev/null; then
        python3 "$HOME/.local/bin/clip-image-server" \
            >>"$HOME/clip-image-server.log" 2>&1 &
        pid=$!
        local i
        for i in {1..50}; do
            nc -z 127.0.0.1 "$local_port" 2>/dev/null && break
            sleep 0.1
        done
        nc -z 127.0.0.1 "$local_port" 2>/dev/null ||
            print -u2 "clip_et: clipboard bridge failed to start on :$local_port (see ~/clip-image-server.log)"
    fi
    _clip_lap "bridge ready"

    # etserver binds a reverse-tunnel port globally, not per session, so two
    # sessions sharing one port kill each other. Claim a port by BINDING it,
    # never by asking whether it is free: asking and using the answer later is a
    # TOCTOU wide enough to drive the whole handshake through. The answer comes
    # from server state every client is racing to change, so several machines
    # asking at once are all told the same port is free — and etserver's second
    # listen() is a hard abort() (TcpSocketHandler.cpp:156) that kills EVERY
    # session on the host, not just the loser. So the bind IS the test.
    #
    # Probe over ONE multiplexed connection rather than logging in per port:
    # sshd still performs the listen() and reports the failure, so the guarantee
    # is unchanged, but a taken port costs a round trip (~0.3s) instead of a full
    # handshake (~3s). That is not a micro-optimisation — every port below the
    # first free one is held by a live session, so the walk happens on every
    # connect, and at this RTT the login-per-port version took >20s to open a
    # terminal.
    #
    # Call the ssh BINARY, never the bare word. Warp rewrites ssh invocations to
    # reuse its own connection (warpify.ssh.reuse_existing_control_master) and
    # PREPENDS -o ControlMaster=yes -o ControlPath=~/.ssh/<hash> -t. ssh keeps the
    # FIRST value of an option, so its path wins and ours is never created: the
    # probes then address a socket we do not own (hangs for minutes) and -O exit
    # would tear down WARP's master, dropping every other session on it. An
    # absolute path dodges the rewrite whether it is an alias, a function or a
    # PATH shim, since all three only match the bare word.
    local SSH=/usr/bin/ssh
    [[ -x $SSH ]] || SSH=$(whence -p ssh) || SSH=ssh

    # The clipboard is a convenience; it must NEVER gate the terminal. Claim the
    # port in the background and hand off to et immediately, so opening a session
    # costs et's own connect and nothing else — however slow, rewritten or
    # contended the tunnel setup turns out to be. The tunnel attaches a moment
    # into the session; a paste in the first seconds may need one retry, and the
    # shim already refuses rather than guesses when no tunnel is attributable.
    ctl="${TMPDIR:-/tmp}/clip-et-$$-${RANDOM}.ctl"
    local claimer=
    {
        if $SSH -o ControlMaster=yes -o ControlPath="$ctl" \
                -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
                -o ConnectTimeout=10 -o BatchMode=yes \
                -fN "$host" 2>/dev/null && [[ -S $ctl ]]
        then
            _clip_lap "master up"
            local p
            for p in {${port_min}..${port_max}}; do
                if $SSH -O forward -R "${p}:127.0.0.1:${local_port}" \
                        -o ControlPath="$ctl" "$host" 2>/dev/null
                then
                    remote_port=$p
                    break
                fi
            done
            _clip_lap "port ${remote_port:-none} claimed"
            # An idle master with no forward is just a leak
            [[ -n $remote_port ]] || $SSH -O exit -o ControlPath="$ctl" "$host" 2>/dev/null
        fi
    } &!
    claimer=$!   # &! disowns, so zsh never prints a job-control line over the session

    # Deliberately no -r: etserver never listen()s on our behalf, so the abort
    # above is unreachable rather than merely less likely.
    _clip_lap "handing off to et"
    et "$@" "$host"
    local rc=$?

    # Stop a claim still in flight, so a slow or wedged one cannot outlive the
    # session it was for. Killing the subshell does not reap an ssh -fN that has
    # already detached, so give its socket a moment to appear — otherwise a master
    # born just after teardown holds its port for good, and leaked ports are what
    # made this slow in the first place. This runs after et has exited, so the
    # wait is invisible.
    if [[ -n $claimer ]]; then
        kill "$claimer" 2>/dev/null
        local w
        for w in {1..8}; do
            [[ -S $ctl ]] && break
            sleep 0.2
        done
    fi

    # The tunnel still dies with the session. Guarded on the socket being ours:
    # -O exit against a control path we did not create would close someone else's
    # master and take their sessions with it.
    if [[ -n $ctl ]]; then
        [[ -S $ctl ]] && $SSH -O exit -o ControlPath="$ctl" "$host" 2>/dev/null
        # A master whose handshake outlived the wait above would otherwise hold its
        # port for good, and accumulated ports are what made connecting slow to
        # begin with. This control path is unique to this invocation, so it can
        # only ever match our own ssh — never Warp's master or another session's.
        ( sleep 12; pkill -f "ControlPath=$ctl" 2>/dev/null; rm -f "$ctl" ) >/dev/null 2>&1 &!
        rm -f "$ctl"
    fi

    # Stop the bridge only if we started it and no other session is still
    # tunnelling. Match on the ControlPath, not on -R: the forward is now
    # requested over the mux, so it no longer appears in the master's argv and
    # matching it would miss live sessions and kill the bridge under them. If our
    # own master is still winding down we simply leave the bridge up, which is
    # the harmless direction to be wrong in.
    if [[ -n $pid ]] &&
       ! pgrep -f "ControlPath=${TMPDIR:-/tmp}/clip-et-" >/dev/null 2>&1; then
        kill "$pid" 2>/dev/null
    fi
    return $rc
}

alias myserver="clip_et user@host"

Deliberately not a launch agent or systemd unit: the bridge exists only alongside a connection, so nothing is listening on your machine while you're not connected.

Eternal Terminal on a busy server

Lessons from one host carrying many concurrent ET sessions from more than one machine. Most of them only show up once there is more than one session.

et -x takes your live sessions too

etserver keeps sessions alive so you can resume them, so abandoned ones pile up as etterminal processes. et -x sweeps them by running pkill etterminal -u <user> before it logs in. That kills every session you have on the host, including the live ones in your other tabs. Use it only when this is your only session; otherwise kill the specific leftover PIDs.

ET roams; the tunnel doesn't

ET survives a closed lid and a changed IP address. The ssh -R next to it is a plain TCP connection, so a network change kills it, and nothing rebuilds it. The session looks healthy but paste stops working. Open a fresh session to get a fresh tunnel. A machine left connected overnight can show every et client still attached and no tunnel left at all.

One log directory per client

et 6.2.x names its client log after the current second and creates it exclusively. If a script opens several sessions at once, all but one abort with FATAL ... createLogFile, and the errno it prints is wrong. Give each client its own directory:

clip_et host --logdir /tmp/et-$RANDOM

Through a jumphost, spell it out

ET reads ProxyJump from ~/.ssh/config, then opens TCP to the alias name and logs in with the destination's user. Pass the jump explicitly. -p is the destination's etserver port as the jumphost sees it. --terminal-path applies to both hops, so use a PATH= prefix rather than an absolute path:

clip_et dest --jumphost user@jump.example.com -p 2023 \
  --terminal-path 'PATH=/opt/homebrew/bin:$PATH etterminal'

The crash reason isn't in the journal

systemd only records status=6/ABRT. The abort() message is in etserver-<start time>_<pid>.log under etserver's logdirectory (default /tmp). The name carries the process's start time, so a crash is in the log of the process started before it.

grep -l 'listen twice' /tmp/etserver-*.log

End with exit; reap the rest

clip_et can only clean up its tunnel after et returns. If you close the window or quit the terminal app instead, the ssh -fN master stays behind. It belongs to init and keeps its remote port for as long as the server stays up. Enough of those and new sessions get no port at all. clip_reap lists them, and clip_reap -f closes them. Its only signal is the shell PID embedded in the control path, so it can miss an orphan but never closes a live tunnel.

Read the port table before calling a leak

On the server, ports held by sshd are current-style tunnels, one per live session. Ports held by etserver are legacy et -r tunnels that clear only when those sessions end. If they squat the bottom of the range, raise CLIP_PORT_MIN past them. Never raise CLIP_PORT_MAX above the shim's PORT_MAX: the shim would never see those ports.

ss -ltnp '( sport >= :8377 and sport <= :8420 )'

Testing et needs a real pty

Without a console fd, et aborts at TerminalClient.cpp:244, so a tty-less harness fails for reasons unrelated to what you are testing. Drive it with expect. For timings, CLIP_ET_DEBUG=1 clip_et host prints each stage. Measure before you guess.

Warp and Claude Code

Things that bite in this particular combination, all of them met while getting the bridge working.

Warp's rc hook can hijack an ET session

Warpify puts a line in the server's ~/.bashrc that prints a SourcedRcFileForWarp escape on every interactive shell. On some Warp builds, seeing it arrive over ET makes Warp open a hidden ssh connection of its own and wait on "Starting shell…" forever, while the ET session is alive the whole time. If yours does this, keep the hook quiet under ET and leave it on for plain ssh. Under ET the shell's parent is etterminal; under ssh it is sshd:

[[ "$-" == *i* ]] \
  && [[ "$(ps -o comm= -p $PPID 2>/dev/null)" != *etterminal* ]] \
  && printf '\eP$f{"hook": "SourcedRcFileForWarp", ...}\x9c'   # Warp's original line

Pin your locale

Warp exports an LC_CTYPE value Linux does not recognise, and both SSH and ET forward it. You get setlocale warnings and mangled box drawing in Claude Code's interface. Put this in your shell rc on the client:

export LANG=en_US.UTF-8
export LC_ALL=en_US.UTF-8

Persistence: tmux by hand, not at login

Running Claude Code inside tmux on the server is fine, and the shim handles it by asking tmux which client is attached now. Don't auto-start it from a login hook to survive etserver crashes, though. tmux does not stop the crash, it only lets you re-attach afterwards. Fix the crash (no et -r) and leave login alone. A client-side dtach around clip_et survives quitting the terminal app, but Warp's blocks stop working through it.

Claude Code hides from scripts

ssh host 'claude --version' can fail while the same command works once you are logged in. ~/.local/bin is added by ~/.profile, which non-interactive shells never read. Use the full path when scripting.

Warp's shell integration leaks into pipes

Capture an ET session's output to a file and you will find a SourcedRcFileForWarp JSON line mixed in with terminal escapes. Pipe through strings when you are trying to read what actually happened. It is harmless in a file. Echo that raw stream back into a Warp pane, from a script or a tool, and Warp acts on the hook as if the server had sent it.

Ctrl+V is not Cmd+V

Warp binds paste to Cmd+V, which sends clipboard text and never reaches Claude Code's image handler. Ctrl+V is unbound and passes through as a raw ^V. That is the key this whole setup depends on.

Before you trust it

Who can read your clipboard

While the tunnel is up, anyone with shell access on that server can pull whatever image is on your clipboard. That is fine for a machine you own and bad for a shared one. The token limits casual access, not a determined user who can read the shim.

If a future release changes this

The two commands were read out of the Claude Code binary, version 2.1.220. If pasting stops working after an upgrade, confirm the mechanism is still the same before debugging anything else:

strings -a ~/.local/share/claude/versions/<version> \
  | grep -F 'xclip -selection clipboard -t TARGETS'

Tested with Claude Code 2.1.220 on both ends: macOS client, Ubuntu 24.04 server, over Eternal Terminal and OpenSSH. A PNG round-tripped byte-identical across both transports. In daily use since with et 6.2.x clients against etserver 7.0.0, with several sessions open at once.
